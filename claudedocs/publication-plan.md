# GitHub Pages 公開計画（2026-10-29）

連載8回を、`yamaguchiyoshito/multi-scale-time` と同じ方式で GitHub Pages に公開するための計画。参考サイトの仕組みを調べた結果と、この連載に合わせて変える点、作業の順序をまとめる。

## 参考サイトの仕組み

- 原本は `chapters/*.md`（Markdown）と `assets/illustrations/*.svg`（挿絵）。`series.json` が回の順序、題名、副題、概要、部の区切り、各回の図と出典の一覧を持つ。
- `scripts/build.py` が Pandoc 3.x で Markdown を HTML に変換し、`site-src/styles.css` を埋め込んで `_site/` を生成する。目次ページは README の前半（`<!-- SITE-INDEX-END -->` より前）から作る。全回を1ファイルにまとめた `complete.html` も出す。
- `scripts/validate.py` が題名と `series.json` の一致、前後ナビの有無、図の番号と順序、脚注と出典の整合、SVG の安全性（script や外部参照の禁止）を検査する。`scripts/check_html.py` が生成後の相対リンクと外部依存を検査する。`tests/` に回帰試験がある。
- 挿絵は `scripts/draw_figures.py` が標準ライブラリだけで決定論的に生成する。1枚につき主張は1つ、パネルは2枚まで、ラベルは10個前後、文字は14px以上。`viewBox`、`role="img"`、`title`、`desc` を持ち、フォントや外部画像を同梱しない。
- 図は本文で説明し終えた段落の直後に `![代替テキスト](../assets/illustrations/NN-x-slug.svg)` で置き、直後に `*図N-k：前提と帰結*` のキャプション段落を置く。密度は本文1,100〜2,000字に1枚（1回あたり5〜12枚）。
- 公開は `main` への push で `.github/workflows/pages.yml` が検査、ビルド、配置を行う。Pages の Source は GitHub Actions。ライセンスは CC BY 4.0。

## この連載に合わせて変える点

参考サイトの検査と試験は、その連載の原稿規則を前提にしている。この連載の文体ルール（references/）と衝突する点は、原稿ではなく検査側を変える。

| 項目 | 参考サイトの前提 | この連載での扱い |
| --- | --- | --- |
| 題名の形式 | `# 第N回　題名`（全角空白） | 現在の「第N回：」を全角空白に揃える。題名の文言は変えない |
| 章の置き場所 | `chapters/` | `articles/` を `chapters/` に改名する。検査がこの名前を前提にしている |
| 節見出し | `### 1. 見出し`（番号付き） | 番号なしを保つ。見出しの階層は `##` から `###` に下げ、検査スクリプトと試験の番号要求を外す |
| 次回予告 | `**次回｜第N回「題名」**` の太字 | 区切り線の下の1行を保つ。試験の文字列要求を本連載の形式に合わせる。最終回は「（全8回・完）」を後書きに添える |
| 脚注と出典 | 本文に `[^id]` 脚注、末尾に「参考文献・注記」、`references/sources.json` | 各回末尾の「扱った作品」の注を脚注形式に移し、作品と哲学書の書誌を `sources.json` に持つ。本文側は作品の初出に脚注番号を付けるだけで、文章は変えない |
| 図の密度 | 5〜12枚 | 4〜7枚（本文1,300字前後に1枚）。冒頭と結末の「私」の場面、および結末直前の段落には置かない。読後の余韻を図で回収しない |
| 図のキャプション | 斜体1段落 | 同じ形式。文体ルールに「図の置き方」の項を追加する |
| 前後ナビ | `<!-- NAV:TOP -->` と `<!-- NAV:BOTTOM -->` | 同じ形式で追加する |

## 決めてほしいこと

1. 連載の題名とコード名。候補は題名「書かれたものを生きる」、コード名「LIVING THE WRITTEN」、副題「時間・因果・自由・記憶・物語・虚構・持続の哲学、全8回」、一行の標語「すべてが決まっていたとしても、すべてはまだ生きられていない。」。
2. 部の区切り。候補は第I部「時間と因果と自由」（1〜3回）、第II部「記憶と物語」（4〜5回）、第III部「虚構と持続と存在」（6〜8回）。
3. リポジトリ名と公開範囲。候補は `yamaguchiyoshito/living-the-written`、公開。
4. ライセンス。参考サイトと同じ CC BY 4.0 を候補とする。引用した作品の著作権は各権利者にあり、本文と図とスクリプトだけが対象になる。
5. 脚注方式に移すか、現在の注段落のままにするか。脚注方式なら参考文献ページが自動生成され、参考サイトと揃う。

## 作業の順序

### 第1段階：骨格の移植と原稿の整形（2026-10-29 完了）

実施時の変更点：文体ルールは `references/` を書誌に明け渡し `guides/STYLE.md` と `guides/style-*.md` へ移した。図の規則は `guides/EDITING.md` に置いた。試験の「節見出しの番号」「太字の次回予告」「各回2枚以上の図」の要求は本連載の規則に合わせて書き換え、図の枚数の要求は第2段階で戻す。末尾ナビの「次回」の自動付与は本文の次回行と重複するため `series.json` の `nav_next_note` で任意にした。

1. 参考リポジトリから `scripts/build.py`、`scripts/validate.py`、`scripts/check_html.py`、`scripts/bibliography.py`、`tests/`、`site-src/styles.css`、`.github/workflows/`、`.gitignore`、`.editorconfig`、`LICENSE` を取り込む。
2. `series.json` を書く（題名、副題、概要、部、各回の slug と題名）。
3. 原稿を整形する。題名の全角空白、`articles/` → `chapters/`、節見出しを `###` に、前後ナビの追加、注段落の脚注化、`references/sources.json` の作成。本文の文章は変えない。
4. 検査と試験を本連載の規則に合わせて直し、図が表紙だけの状態で `validate.py`、`unittest`、`build.py`、`check_html.py` を通す。
5. README を目次ページとして書く（表紙、標語、導入の一段落、全8回の目次、部の説明）。`guides/` に読み方と公開手順を置く。文体ルール（references/）に図の規則を足す。
6. `scripts/check_rhythm.py` を `chapters/` と `###` に合わせる。

### 第2段階：挿絵（2026-10-29 完了）

実施時の変更点：図の計画は `claudedocs/figure-plan.md`（表紙を除き47枚、回ごとに5〜7枚）。描画コードは回ごとに `scripts/figures/chNN.py` に分け、`draw_figures.py --chapter N` で1回分だけ描き直せるようにした。目視確認用に `scripts/render_png.sh` を置いた。

1. 図の計画を `claudedocs/figure-plan.md` に書く。回ごとに、図を置く段落、1枚の主張、パネル構成、ラベル候補を列挙する。目安は全体で45枚前後と表紙1枚。
2. 計画を確認してもらってから `scripts/draw_figures.py` を実装し、SVG を生成する。
3. 本文に図とキャプションを挿入し、`series.json` の `figures` を更新する。
4. 検査、試験、ビルドを通し、ブラウザでデスクトップ幅とスマートフォン幅の表示を確認する。横はみ出し、欠けた日本語、切れた図の文字を直す。

図の候補（回ごとの主題から）：第1回は逐次的認識と同時的認識の対比、映画のフィルムと観客、ヘプタポッドBの全体先行、予測と記憶の違い、時間をめぐる三つの問題。第2回は踏み分け道と最短経路、フェルマーの原理の経路、各時点の法則と経路全体の条件、因果ループの構造、結末から始まりを理解する向き。第3回は未来を記した書物、二つの自由、ルイーズとエレンの対比、遂行的な発話。第4回はエマノンとヒカリの時間線、初対面と再会の非対称、出来事の位置と日付。第5回は出来事と意味の分離、後続作品が先行作品を読み替える向き、書く浜崎正と書かれる浜崎正、三つの存在の水準。第6回は三つのりんごと数の3、虚構の外へ出る物語と出られない物語、並行世界と反復、知ることと行為すること。第7回は描いている絵と描き終えた絵、持続と百夜、二種類の未完了、完成による関係の変化。第8回は七つの議論の見取り図、記述と経験の差、確定した人生と未完了の経験。

### 第3段階：公開

1. `git init`、初回コミット。生成物 `_site/` は `.gitignore` で除外する。
2. `gh repo create yamaguchiyoshito/living-the-written --public --source=. --remote=origin --push`。
3. `gh api -X POST repos/yamaguchiyoshito/living-the-written/pages -f build_type=workflow` で Pages を GitHub Actions 方式にする。
4. Actions の `Publish to GitHub Pages` の完了を確認し、`github-pages` 環境の URL を実際に開いて目視する。推測した URL を案内しない。
